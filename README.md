# Soroban Quest — тренажёр ментальной арифметики в игровой форме

Учебный проект: серверная часть приложения, которое превращает ежедневные занятия
ментальной арифметикой (соробан, флеш-анзан) в игру с очками, уровнями, сериями
и соревнованием между учениками.

> **Статус:** лабораторная работа №1 — серверная часть (модульный монолит).
> Клиентское приложение (лаба №2) будет жить в каталоге [`client/`](client/README.md).

---

## 1. Зачем это приложение

**Проблема.** Ментальной арифметике учат в офлайн-школах: ребёнок занимается
2 раза в неделю с преподавателем, а навык требует ежедневной короткой практики.
Дома практиковаться скучно: нужен человек, который диктует примеры, проверяет
ответы и следит за прогрессом. Готовые «генераторы примеров» в интернете не ведут
историю, не подстраивают сложность и не дают мотивации заниматься каждый день.

**Решение.** Приложение заменяет «того, кто диктует и проверяет»:

* **генерирует задания** по правилам соробана (цепочки без ухода в минус,
  деление всегда нацело, флеш-анзан с нарастающей скоростью показа);
* **судит честно** — правильный ответ считает сервер, клиент его не знает,
  пока не ответит, а скорость ответа влияет на очки;
* **удерживает привычку** — дневная цель, серии дней подряд, достижения;
* **даёт соревнование** — недельный и общий рейтинг среди всех учеников.

**Для кого:** ученики школ ментальной арифметики (7–14 лет) и их родители;
взрослые, которые тренируют устный счёт; преподаватели, которым нужна
объективная статистика по ученику.

**Почему нужен сервер, а не просто приложение на телефоне:**

| Требование | Что даёт сервер |
|---|---|
| Нельзя подсмотреть ответ | Задания воспроизводятся из `seed` на сервере, ответ не уезжает клиенту заранее |
| Честный рейтинг | Очки и опыт считаются только серверной бизнес-логикой |
| Прогресс не теряется | История тренировок, серии и достижения живут в PostgreSQL |
| Несколько устройств | Телефон, планшет и веб видят один и тот же профиль |
| Отчёт преподавателю | Разбор каждого ответа: что ответил, что было верно, сколько думал |

### Игровой цикл

```
выбор режима → тренировка (N заданий) → очки за каждый ответ (скорость × комбо)
      ↑                                              ↓
  рейтинг ← опыт, уровень, серия, достижения ← итог тренировки
```

## 2. Что реализовано

**Тренировки (5 режимов):** флеш-анзан, цепочка «плюс-минус», умножение,
деление нацело, смешанный режим. 10 уровней сложности влияют на разрядность
чисел, количество слагаемых, скорость показа и лимит времени.

**Жизненный цикл тренировки:** старт → выдача задания → проверка ответа на
сервере → начисление очков (база по сложности × коэффициент скорости × множитель
комбо) → автозавершение после последнего задания либо досрочное прерывание.
Повторная отправка ответа идемпотентна, ответы «не по порядку» отклоняются.

**Аккаунты:** регистрация, вход, access-токен (JWT, 30 мин) + refresh-токен
(30 дней) с ротацией и обнаружением повторного использования украденного токена.
Пароли — BCrypt, refresh-токены хранятся только в виде SHA-256.

**Прогресс:** опыт и уровни по явной кривой, серии дней подряд, дневная цель,
статистика по каждому режиму (точность, рекорд скорости, лучший результат),
11 достижений с правилами.

**Соревнование:** недельный (по ISO-неделям) и общий рейтинг, место пользователя
возвращается, даже если он не попал в топ.

**Инфраструктура:** PostgreSQL + миграции Flyway (по схеме на модуль), RFC 7807
(`application/problem+json`) для всех ошибок, OpenAPI/Swagger UI, health-проба,
сквозной `X-Request-Id` в логах, запуск одной командой через Docker Compose,
59 тестов (модульные + интеграционные на настоящей БД в Testcontainers).

## 3. Архитектура

Модульный монолит: одно приложение, но внутри — независимые модули со своими
доменом, хранилищем и контрактом. Пакет `api` каждого модуля публичный, всё
остальное помечено Kotlin-модификатором `internal`, поэтому **границы модулей
проверяет компилятор**, а не договорённости в команде.

```
                     ┌──────────────────────────────┐
  HTTP-клиенты  ───▶ │  api:rest  (контроллеры, DTO,│
                     │  валидация, JWT-фильтр)      │
                     └───────────────┬──────────────┘
                 только публичные контракты модулей
     ┌───────────────┬───────────────┼────────────────┬──────────────┐
     ▼               ▼               ▼                ▼              │
┌──────────┐  ┌────────────┐  ┌──────────────┐  ┌─────────────┐      │
│ identity │  │  training  │  │ progression  │  │ leaderboard │      │
│ вход,    │  │ генерация  │  │ опыт, серии, │  │ недельный и │      │
│ токены   │  │ заданий,   │  │ достижения   │  │ общий топ   │      │
│          │  │ сессии,    │  │              │  │             │      │
│          │  │ очки       │  │              │  │             │      │
└────┬─────┘  └─────┬──────┘  └──────┬───────┘  └──────┬──────┘      │
     │ UserRegistered│ SessionCompleted│ XpAwarded      │             │
     └──────────────▶└────────────────▶└───────────────▶│             │
                        (доменные события, синхронно)                 │
     ┌────────────────────────────────────────────────────────────┐   │
     │ shared: идентификаторы, ошибки, порты событий и транзакций │◀──┘
     └────────────────────────────────────────────────────────────┘
     ┌────────────────────────────────────────────────────────────┐
     │ bootstrap: Spring Boot, реализации портов, конфигурация     │
     └────────────────────────────────────────────────────────────┘
```

### Модули

| Модуль | Ответственность | Публичный контракт |
|---|---|---|
| `shared` | Идентификаторы, иерархия ошибок, порты транзакций/событий/ID, пагинация | весь модуль |
| `modules/identity` | Регистрация, вход, выпуск и ротация токенов, справочник пользователей | `AuthenticationService`, `UserDirectory`, `AccessTokenVerifier` |
| `modules/training` | Каталог режимов, детерминированная генерация заданий, агрегат сессии, начисление очков | `TrainingService`, событие `TrainingSessionCompleted` |
| `modules/progression` | Опыт, уровни, серии, дневная цель, мастерство по режимам, достижения | `ProgressionService`, событие `XpAwarded` |
| `modules/leaderboard` | Недельный и общий рейтинг | `LeaderboardService` |
| `api/rest` | HTTP: контроллеры, DTO, валидация, маппинг ошибок, безопасность, OpenAPI | — |
| `bootstrap` | Composition root: Spring Boot, транзакции, шина событий, конфигурация, Docker | — |

### Слои внутри бизнес-модуля

```
api/                 публичные типы и интерфейсы — всё, что видят другие модули
internal/domain/     чистый Kotlin: агрегаты, политики, инварианты (без Spring и SQL)
internal/application/сценарии: оркестрация домена, портов хранения и событий
internal/persistence/адаптеры к PostgreSQL (JDBC), реализуют порты из application
internal/config/     единственное место, где модуль соприкасается со Spring (@Bean)
```

Домен не знает ни про HTTP, ни про Spring, ни про SQL. Транзакции и события
доступны ему через порты `TransactionRunner` и `DomainEventPublisher`, реализации
которых живут в `bootstrap`.

### Почему так, а не иначе

| Решение | Зачем |
|---|---|
| Задания не хранятся, а воспроизводятся из `(seed, номер)` | Клиент не может подсмотреть ответ; БД не растёт от заданий; результат можно перепроверить |
| Межмодульные вызовы — только через `api`, остальное `internal` | Нарушение границы модуля не компилируется |
| События синхронные и в одной транзакции с издателем | Очки, опыт и рейтинг не могут разъехаться; при желании заменяются на очередь — меняется одна реализация порта |
| Схема БД на каждый модуль, без межмодульных внешних ключей | Границы модулей видны и в БД; модуль можно вынести в отдельный сервис |
| JDBC вместо ORM | Доменные классы остаются чистыми (без аннотаций), SQL явный и предсказуемый, видно, где берётся блокировка |
| `select ... for update` + оптимистичная версия + `on conflict` | Защита от гонок на трёх уровнях: сессия, профиль, повторные ответы |
| Ошибки домена с кодом, HTTP-статус выбирается в REST-слое | Бизнес-логика не зависит от протокола: gRPC/GraphQL-слой добавляется без её правок |

## 4. Технологии

| Технология | Для чего |
|---|---|
| **Kotlin 2.2 / JDK 21** | Язык реализации; `internal` обеспечивает границы модулей, data-классы — неизменяемый домен |
| **Gradle (Kotlin DSL) + version catalog** | Мультимодульная сборка; версии зависимостей — только в `gradle/libs.versions.toml` |
| **Spring Boot 3.5** (web, jdbc, security, validation, actuator) | HTTP-сервер, пул соединений, транзакции, фильтры безопасности, health-проба |
| **PostgreSQL 17** | Хранение; нужны `on conflict`, оконные функции (`rank()`), блокировки строк |
| **Flyway** | Версионируемые миграции схемы; каждая миграция лежит в своём модуле |
| **jjwt 0.12** | Подпись и проверка JWT (HS256) |
| **spring-security-crypto** | BCrypt для паролей |
| **springdoc-openapi** | Живая документация API и Swagger UI |
| **kotlin-logging (SLF4J)** | Логирование с ленивым форматированием сообщений |
| **JUnit 5 + AssertJ + Testcontainers** | Модульные тесты домена и интеграционные тесты на настоящем PostgreSQL |

## 5. Как запустить

### Вариант 1. Docker Compose (рекомендуемый)

```bash
cd server
cp .env.example .env
# подставьте свой секрет: openssl rand -base64 48  (или head -c 48 /dev/urandom | base64)
docker compose up --build -d
```

Готово:

* API — <http://localhost:8080/api/v1>
* Swagger UI — <http://localhost:8080/swagger-ui.html>
* Health — <http://localhost:8080/actuator/health>

Остановить: `docker compose down` (с удалением данных — `docker compose down -v`).

> Если порт 5432 занят локальным PostgreSQL, поменяйте `POSTGRES_PORT` в `.env`.

### Вариант 2. Локально (Gradle + PostgreSQL в Docker)

```bash
cd server
docker compose up -d postgres
export DATABASE_URL=jdbc:postgresql://localhost:5432/soroban
export DATABASE_USER=soroban
export DATABASE_PASSWORD=soroban-local-password
export SOROBAN_JWT_SECRET=$(head -c 48 /dev/urandom | base64)
./gradlew :bootstrap:bootRun
```

### Проверить, что всё работает

```bash
python3 server/scripts/demo.py            # сквозной сценарий: регистрация → тренировка → профиль → рейтинг
```

Скрипт без зависимостей: регистрирует ученика, проходит тренировку из 10 заданий
(одно — с намеренной ошибкой), печатает очки за каждый ответ, итоговый профиль,
достижения, рейтинг и демонстрирует идемпотентность повторного ответа.

### Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATABASE_URL` | `jdbc:postgresql://localhost:5432/soroban` | JDBC-строка подключения |
| `DATABASE_USER` / `DATABASE_PASSWORD` | `soroban` / — | Учётные данные БД |
| `SOROBAN_JWT_SECRET` | — (**обязательна**) | Ключ подписи JWT, минимум 32 байта |
| `SOROBAN_ACCESS_TOKEN_TTL` | `PT30M` | Время жизни access-токена |
| `SOROBAN_REFRESH_TOKEN_TTL` | `P30D` | Время жизни refresh-токена |
| `SOROBAN_TIME_ZONE` | `UTC` | Пояс, по которому считаются дни серий и границы недели |
| `SOROBAN_MAX_ACTIVE_SESSIONS` | `5` | Лимит незавершённых тренировок на пользователя |
| `SERVER_PORT` | `8080` | Порт HTTP |
| `LOG_LEVEL` | `INFO` | Уровень логов приложения |

Секретов в коде нет: приложение не стартует, если `SOROBAN_JWT_SECRET` не задан
или короче 32 байт.

## 6. API

Полное описание — в Swagger UI или в [`docs/api.md`](docs/api.md).

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/auth/register` | Регистрация, сразу выдаёт пару токенов |
| `POST` | `/api/v1/auth/login` | Вход |
| `POST` | `/api/v1/auth/refresh` | Обновление пары токенов (с ротацией) |
| `POST` | `/api/v1/auth/logout` | Отзыв refresh-токена |
| `GET` | `/api/v1/training/drills` | Каталог режимов тренировок |
| `POST` | `/api/v1/training/sessions` | Начать тренировку (в ответе — первое задание) |
| `GET` | `/api/v1/training/sessions/{id}` | Состояние тренировки и текущее задание |
| `POST` | `/api/v1/training/sessions/{id}/answers` | Ответ на задание (идемпотентно) |
| `POST` | `/api/v1/training/sessions/{id}/abandon` | Прервать тренировку |
| `GET` | `/api/v1/training/sessions/{id}/answers` | Разбор ответов |
| `GET` | `/api/v1/training/sessions` | История тренировок (постранично) |
| `GET` | `/api/v1/me` | Профиль: уровень, опыт, серия, точность |
| `GET` | `/api/v1/me/achievements` | Достижения (открытые и закрытые) |
| `GET` | `/api/v1/me/skills` | Статистика по режимам |
| `GET` | `/api/v1/me/daily?days=7` | Активность по дням |
| `PUT` | `/api/v1/me/daily-goal` | Изменить дневную цель |
| `GET` | `/api/v1/leaderboard?period=WEEKLY` | Таблица лидеров |

Все ошибки — в формате RFC 7807:

```json
{
  "type": "https://sorobanquest.dev/errors/rule_violation",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "Ожидается ответ на задание №0, получен №3",
  "instance": "/api/v1/training/sessions/7b1.../answers",
  "code": "RULE_VIOLATION",
  "rule": "task_out_of_order",
  "expectedTaskIndex": 0,
  "receivedTaskIndex": 3
}
```

Соответствие кодов и статусов: `VALIDATION_FAILED` → 400, `UNAUTHORIZED` → 401,
`FORBIDDEN` → 403, `NOT_FOUND` → 404, `CONFLICT` → 409, `RULE_VIOLATION` → 422.

## 7. Модель данных

Каждый модуль владеет собственной схемой PostgreSQL:

| Схема | Таблицы | Особенности |
|---|---|---|
| `identity` | `users`, `refresh_tokens` | Уникальный индекс по `lower(email)`; хранится SHA-256 refresh-токена |
| `training` | `practice_sessions`, `session_answers` | Поле `version` для оптимистичной блокировки; PK `(session_id, task_index)` даёт идемпотентность |
| `progression` | `learner_profiles`, `achievements`, `skill_mastery`, `daily_progress` | PK `(user_id, code)` не даёт выдать достижение дважды; дневной опыт инкрементируется через `on conflict do update` |
| `leaderboard` | `entries` | Агрегат по `(период, участник)`, места считает `rank() over (...)` |

Миграции лежат внутри модулей (`src/main/resources/db/migration/<модуль>`) и
применяются Flyway при старте: версии `1.x` — identity, `2.x` — training,
`3.x` — progression, `4.x` — leaderboard.

## 8. Тесты

```bash
cd server
./gradlew test          # все тесты (для интеграционных нужен запущенный Docker)
./gradlew :modules:training:test   # только домен тренировок, без Docker
```

**Модульные (чистый домен, без инфраструктуры)**

* генераторы: детерминированность по `(seed, номер)`, сумма флеш-анзана,
  неотрицательность цепочки, деление нацело, влияние сложности;
* начисление очков: бонус за скорость, множитель комбо и его потолок;
* агрегат сессии: порядок заданий, завершение, прерывание, валидация времени;
* кривая уровней, политика опыта, логика серий (тот же день / следующий / пропуск);
* правила достижений; ключи ISO-недель; рейтинг с местами и строкой зрителя;
* аутентификация: ротация refresh-токенов и реакция на повторное использование.

**Интеграционные (Testcontainers: настоящий PostgreSQL, Flyway, HTTP-слой)**

* сценарии аутентификации и коды ответов (201/400/401/409);
* полное прохождение тренировки во всех пяти режимах;
* идемпотентность повторного ответа, 422 при нарушении порядка, 403 на чужую
  сессию, лимит незавершённых тренировок;
* связка модулей через события: опыт, серия, достижения, статистика, рейтинг;
* конкурентность: 8 одновременных отправок одного ответа засчитываются один раз;
  4 параллельно завершённые тренировки не теряют опыт.

## 10. Что дальше

  (экраны уже перечислены в [`client/README.md`](client/README.md)).
* Адаптивная сложность: подбор уровня по текущей точности и скорости ученика.
