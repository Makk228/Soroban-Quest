# Soroban Quest — сервер

Серверная часть тренажёра ментальной арифметики. Полное описание проекта,
бизнес-логики и архитектуры — в [корневом README](../README.md) и
[`docs/architecture.md`](../docs/architecture.md).

## Быстрый старт

```bash
cp .env.example .env
# впишите свой SOROBAN_JWT_SECRET (минимум 32 байта)
docker compose up --build -d

python3 scripts/demo.py        # сквозной сценарий: регистрация → тренировка → профиль → рейтинг
```

* API — <http://localhost:8080/api/v1>
* Swagger UI — <http://localhost:8080/swagger-ui.html>
* Health — <http://localhost:8080/actuator/health>

## Сборка и тесты

```bash
./gradlew build                     # сборка + все тесты (нужен Docker для интеграционных)
./gradlew :modules:training:test    # только доменные тесты, без Docker
./gradlew ktlintCheck              # проверка стиля (также входит в check/build)
./gradlew ktlintFormat             # автоформатирование
./gradlew :bootstrap:bootRun        # локальный запуск (нужны переменные окружения)
```

## Структура

| Каталог | Что внутри |
|---|---|
| `shared/` | Идентификаторы, ошибки, порты транзакций и событий |
| `modules/identity/` | Регистрация, вход, JWT, ротация refresh-токенов |
| `modules/training/` | Генерация заданий, сессии тренировок, очки |
| `modules/progression/` | Опыт, уровни, серии, достижения, статистика |

| `bootstrap/` | Spring Boot, конфигурация, реализации портов, интеграционные тесты |
| `scripts/demo.py` | Демонстрационный сценарий без зависимостей |

## Соглашения учебной версии

Код синхронный, без `suspend` и корутин. JDBC сохранён. Kotlin-свойства объявляются
через `val`; новые состояния доменных моделей возвращаются через `copy`.
Параметры функций и конструкторов задаются явно, без Kotlin default arguments.
Фабрики вынесены в именованные объекты; `companion object` отсутствуют.
Значения enum записываются в `UPPER_SNAKE_CASE`.

Jakarta Validation удалена: проверки выполняются обычным Kotlin-кодом,
ошибки обрабатываются в `GlobalExceptionHandler`. Jakarta Servlet остаётся
частью Spring MVC и фильтров безопасности. Отсутствующие и null-поля запросов
отклоняются Jackson; ошибки бизнес-правил проверяются в домене.
Неожиданные ошибки возвращают 500 без внутренних подробностей, с записью в журнал.

В HTTP API сохранены документированные значения необязательных query-параметров
(пагинация, период рейтинга, количество дней). Конфигурация окружения задаётся
в `application.yml`, а не дублируется в конструкторах.

Docker использует многоступенчатую сборку и минимальный runtime `21-jre-alpine`
без JDK и Gradle. BuildKit кеширует зависимости между сборками.

## Миграции после рефакторинга

Начальная история миграций переразбита: схема, таблица и каждый дополнительный
индекс находятся в отдельных файлах. Индексы создаются через
`CREATE INDEX CONCURRENTLY`; соседние `.sql.conf` отключают транзакцию только
для соответствующего файла. Flyway использует session-level advisory lock
(`spring.flyway.postgresql.transactional-lock=false`). Первичные ключи и
UNIQUE-ограничения создаются вместе с новыми пустыми таблицами.

**Эта история рассчитана на новую пустую БД.** Если прежние миграции уже
применены, не запускайте её поверх старой истории Flyway и не делайте `repair`
для обхода проверки. Для учебного запуска создайте отдельную БД/volume;
существующие данные и volume автоматически не удаляются. Для обновления БД
с ценными данными потребуется отдельная стратегия миграции с сохранением старой истории.

Настройки конкурентных индексов сверены с
[документацией Flyway](https://documentation.red-gate.com/flyway/reference/configuration/flyway-namespace/flyway-postgresql-namespace/flyway-postgresql-transactional-lock-setting).
